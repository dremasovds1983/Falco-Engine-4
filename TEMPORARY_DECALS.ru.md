# Временные decals

Добавлен тип материала `Deferred/Temporary Decal` (StandardTemporaryDecal.shader).
Настройки в Inspector материала: Temporary decals, Maximum count (1–200,
по умолчанию 200), Lifetime (seconds) (по умолчанию 60).

Правила:
- Автоматическое управление относится только к экземплярам prefab/клонам,
  созданным во время игры. Размещённые в сцене постоянные decals не удаляются.
- Возраст идёт в игровом времени, с учётом Time.timeScale. Пауза времени
  останавливает старение. Нулевой срок означает удаление при первом выходе из кадра.
- Просроченный след удаляется только вне поля зрения всех активных автоматически
  отрисовываемых игровых камер. Scene и Camera Viewport не учитываются.
  Это проверка объёма по фрустуму и слою камеры, а не GPU occlusion test.
  При отсутствии игровой камеры удаление по сроку отложено.
- Лимит общий для runtime-экземпляров одного объекта материала. При переполнении
  удаляются старейшие экземпляры независимо от видимости. Новые не отклоняются.
- Удаляется GameObject эффекта вместе с его дочерними объектами. Материал временных
  следов следует применять к отдельным объектам эффектов, а не к объекту стены.
- Очистка выполняется после Update скриптов, до отрисовки, штатным механизмом
  удаления движка. Повторное использование материалов/смена оружия не сбрасывает очередь.

Рендер:
Неперекрывающиеся консервативные экранные прямоугольники объединяются в проход.
Первый draw копирует весь исходный G-buffer, остальные используют scissor.
Перекрывающиеся decals назначаются в последующий проход, сохраняя порядок.
Доступно 200 проходов перекрытия; это не предел общего количества неперекрывающихся
статических decals. Переполнение отмечается предупреждением (один раз).
Для области, пересекающей камеру, используется консервативный полный экран.
На backend с originBottomLeft используется полный экран без scissor-оптимизации.
Modern D3D11 — поддерживаемый основной путь.

Сильно перекрывающиеся 200 проекторов по-прежнему требуют до 200 полноэкранных
проходов: производительность такого случая не гарантирована без замера.
Modern bgfx использует 2048 view ID: до семи групп камер, служебные view 2045–2047.
Сохранены диапазоны всех дополнительных окон Scene и Camera Viewport;
выход за бюджет теперь защищён предупреждением вместо конфликта ID.

DemoProject:
Создан `Assets/Decals/BulletHoleTemporary.material` на основе BulletHole.material,
с новой identity и шейдером. `Assets/Prefab/BulletHole.prefab` ссылается на новый
материал. Старый материал сохранён. Резервные копии до изменения:
`D:/DreamOwl_engine/_ai/backups/temporary-decals-20260921/`.
Weapon.cs и строка Instantiate не менялись. Для работы нужен новый движок и
BuiltinResources после следующей разрешённой сборки; Editor следует перезапустить.

Статус: только исходники и статическая проверка diff. Сборки, тесты, commit/push
не выполнялись. ShaderSmoke при следующей сборке автоматически подхватит новый shader.

Ручная проверка после сборки:
1. Более 8 попаданий на стене: все видимы издали и вблизи.
2. Лимит 3, четыре выстрела: исчезает первый, четвёртый всегда виден.
3. Срок 3 секунды: в кадре старые следы сохраняются; после поворота камеры
   и возвращения просроченные следы отсутствуют.
4. Лимит при старых следах вне кадра: новый создаётся, удаляется самый старый.
5. Два материала имеют отдельные лимиты; разные оружия с общим материалом — общий.
6. Постоянные decals сцены и editor-only камеры не влияют на удаление.
7. Перекрывающиеся следы сохраняют текстуры и порядок; проверить края экрана,
   камеру внутри объёма проектора, Scene 2 и Camera Viewport.
8. Сравнить скорость 200 разнесённых следов и 200 следов, перекрывающихся на экране.
